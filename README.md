# Реестр сертификатов курса

Преподаватель регистрирует SHA-256 готового PDF и при необходимости отзывает сертификат. Любой пользователь может проверить свой экземпляр. Даже изменение одного байта даёт другой хеш. Имя файла на результат не влияет. Проверка подтверждает совпадение с экземпляром, зарегистрированным преподавателем курса.

## Текущий локальный запуск

| Параметр | Значение |
| --- | --- |
| Проверка PDF | http://127.0.0.1:3001/verify |
| Выдача и отзыв | http://127.0.0.1:3001/issue |
| RPC Hardhat | http://127.0.0.1:8545 |
| Chain ID / валюта | 31337 / ETH |
| CertificateRegistry | `0x4A679253410272dd5232B3Ff7cF5dbB88f295319` |
| Преподаватель | `0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266` |

Адрес контракта относится к текущему узлу ЛР-11. После перезапуска узла данные локальной сети могут исчезнуть. Команда деплоя выводит актуальный адрес и обновляет ABI и адрес в `packages/nextjs/contracts/deployedContracts.ts`.

## Запуск на Windows 11

Проверено с Node.js 24.18.0, Hardhat 3.18.1, Solidity 0.8.30, Next.js 16.3.8 и Yarn 4.18.1. Выполняйте команды PowerShell из папки `certificate-registry`. Для текущей рабочей копии зависимости уже доступны через локальные ссылки каталогов `packages/*/node_modules` на установку ЛР-9. Исходники, артефакты, деплой и данные фронтенда находятся в папке проекта.

Для установки в **чистой копии проекта** (без каталогов `node_modules`) используйте вложенный Yarn и зафиксированные версии:

```powershell
node .yarn/releases/yarn-4.18.1.cjs install --immutable
```

1. Проверьте существующий узел. В поле `result` должен быть `0x7a69` (31337).

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8545 -Method Post -ContentType application/json -Body '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'
   ```

   Если локальный узел отсутствует, откройте отдельный терминал в папке проекта и оставьте его работающим:

   ```powershell
   npm.cmd --prefix packages/hardhat run chain
   ```

2. Выполните тесты, деплой и проверку типов. Тесты работают в собственной сети в памяти. Деплой использует первый аккаунт локального узла.

   ```powershell
   npm.cmd --prefix packages/hardhat test
   npm.cmd --prefix packages/hardhat run deploy
   npm.cmd --prefix packages/hardhat run check-types
   ```

3. Запустите сайт в отдельном терминале. Если 3001 занят другим процессом, замените порт в команде и в URL обеих страниц. ЛР-11 может продолжать работать на 3000.

   ```powershell
   npm.cmd --prefix packages/nextjs run start -- --port 3001
   ```

4. Откройте обе страницы. Проверить типы интерфейса можно из ещё одного терминала:

   ```powershell
   npm.cmd --prefix packages/nextjs run check-types
   ```

## Демонстрация и три скриншота для отчёта

Добавьте в MetaMask локальную сеть с RPC, Chain ID и валютой из таблицы. Для записи выберите аккаунт с адресом преподавателя. Если его ещё нет в MetaMask, импортируйте **тестовый** аккаунт № 0 из вывода локального Hardhat. Этот публично известный аккаунт предназначен только для локальной сети.

| Кадр | Действие | Что должно быть видно |
| --- | --- | --- |
| 1 | Открыть `/verify` без кошелька и выбрать новый PDF | Имя файла, SHA-256 и «Не зарегистрирован» |
| 2 | На `/issue` подключить MetaMask, выбрать тот же PDF, нажать «Выдать сертификат» и подтвердить | «Действителен», сообщение об успешной выдаче и хеш транзакции |
| 3 | Нажать «Отозвать» и подтвердить в MetaMask | «Отозван», хеш второй транзакции и недоступные кнопки повторной выдачи и отзыва |

Открытая вкладка проверки перечитывает статус каждые три секунды. Можно также выбрать тот же PDF в отдельном окне браузера без расширений. Отказ подписать операцию отображается как ошибка и позволяет повторить попытку.

## Устройство проекта

- `packages/hardhat/contracts/CertificateRegistry.sol` хранит неизменяемый адрес преподавателя и статус каждого хеша. `getStatus` возвращает 0, 1 или 2. Допустимые переходы — выдача (0 → 1) и окончательный отзыв (1 → 2). Оба испускают `CertificateStatusChanged(bytes32 indexed fileHash, Status newStatus)`.
- `packages/hardhat/test/CertificateRegistry.ts` проверяет чтение посторонним адресом, выдачу и отзыв, аргументы обоих событий, ограничения прав, нулевой хеш, повторную выдачу и недопустимые отзывы.
- `packages/hardhat/deploy/` и `rocketh/` используют схему деплоя Scaffold-ETH 2 из лабораторной. Задача деплоя экспортирует описание контракта для фронтенда из результата Rocketh.
- `packages/nextjs/app/pdfHash.ts` проверяет заголовок PDF и вызывает Web Crypto `crypto.subtle.digest("SHA-256", bytes)` для всех исходных байтов. Обе страницы используют одну форму. В RPC передаются хеш и данные вызова контракта, сам PDF остаётся в браузере.
- Фронтенд использует Next.js App Router и хуки Wagmi из стека Scaffold-ETH 2. Публичный HTTP-клиент читает контракт независимо от MetaMask. Запись требует сеть 31337 и адрес преподавателя. После получения квитанции форма отдельно запрашивает статус.
